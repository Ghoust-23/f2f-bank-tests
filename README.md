# F2F Bank — E2E Tests

End-to-end тесты для приложения F2F Bank, написанные с использованием Playwright и TypeScript.

## Запуск приложения

### Требования

Для запуска приложения необходимы:

- Docker Desktop
- Docker Compose v2+
- Node.js 18+
- Git

### Запуск

1. Запустить Docker Desktop.

2. В корневой директории проекта выполнить:

```bash
docker compose up -d --build
```

3. После запуска контейнеров приложение будет доступно по адресу:

`http://localhost`

### Остановка приложения

Для остановки приложения:

```bash
docker compose down
```

Для остановки приложения с удалением данных из базы:

```bash
docker compose down -v
```

## Запуск автотестов

Перед первым запуском установить зависимости:

```bash
npm install
```

Установить браузеры Playwright:

```bash
npx playwright install
```

Запуск всех тестов:

```bash
npx playwright test
```

Запуск тестов в UI-режиме:

```bash
npx playwright test --ui
```

Просмотр HTML-отчёта после выполнения тестов:

```bash
npx playwright show-report
```

## Выявленные проблемы

### Проверка валидации Name и Surname при регистрации

**Приоритет:** Medium

**Проверяемая функциональность:**  
Валидация допустимых значений в полях Name и Surname.

**Входные данные:**  
Name и Surname, содержащие спецсимволы или только цифры.

**Шаги:**

1. Пользователь перешел на страницу регистрации `http://localhost/register`
2. Пользователь заполнил Name и Surname спецсимволами или цифрами
3. Пользователь заполнил Email и Password валидными данными
4. Пользователь нажал кнопку "Register"

**Ожидаемый результат:**  
В требованиях не указаны ограничения на допустимые символы в Name и Surname.

**Фактический результат:**  
Регистрация успешно выполняется с цифрами и спецсимволами в полях Name и Surname.

### Проверка валидации пароля при регистрации

**Приоритет:** Medium

**Проверяемая функциональность:**  
Валидация поля Password при регистрации.

**Входные данные:**  
Name, Surname, валидный Email, Password длиной 1 символ.

**Шаги:**

1. Пользователь перешел на страницу регистрации `http://localhost/register`
2. Пользователь заполнил Name, Surname и Email валидными данными
3. Пользователь ввел в поле Password один символ
4. Пользователь нажал кнопку "Register"

**Ожидаемый результат:**  
В требованиях не указаны ограничения на минимальную длину и сложность пароля, поэтому однозначный ожидаемый результат определить нельзя.

**Фактический результат:**  
Пользователь успешно регистрируется с паролем длиной 1 символ.

### Проверка отображения баланса после повторной авторизации

**Приоритет:** Medium

**Проверяемая функциональность:**  
Отображение баланса пользователя после повторного входа в аккаунт.

**Входные данные:**

**Раздел:** Transactions

**Описание:**  
На странице `http://localhost/transactions` большая часть текста в таблице отображается очень светлым цветом на светлом фоне.

**Фактическое поведение:**  
Заголовки таблицы, Operation ID, дата, тип и статус операции имеют низкую контрастность относительно фона, из-за чего информация о транзакциях плохо читается.
